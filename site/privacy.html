Privacy Policy

Prepared 21 October 2026. This is a working draft, not legal advice. It requires review against the deployed configuration before publication.

Before publication

The operator identity, contact details, hosting location, retention period, processor list and data-subject request process are not confirmed. Items marked as requiring confirmation must be completed. Do not use this draft as a final privacy notice.

1. Scope and status

This policy describes the current MILAAN website and local demonstration. MILAAN is an early-stage GST invoice reconciliation project. The operator responsible for the service is [To be confirmed].

The demo is designed for synthetic records. It should not be used with real taxpayer, supplier or personal data until a production data-handling arrangement has been reviewed.

2. Data processed by the website

The static product website has no account system, contact form, payment flow, newsletter sign-up or marketing analytics in its own code. It does not ask for personal information.

The hosting provider and server used to deliver the website may process standard technical information such as IP address, request time, browser information and requested pages in access logs. The hosting configuration for a public deployment has not been verified.

3. Data processed by the demo

The Streamlit demo can process the following categories when a user interacts with it:

  • Supplier names, GSTINs and phone numbers in the synthetic demo database.
  • Purchase invoice fields, amounts, tax periods and validation results.
  • Uploaded GSTR-2B rows, file names, file hashes, raw source values and row-level errors.
  • Reconciliation runs, matched and unmatched evidence, and status classifications.
  • Follow-up draft text, draft status events and approval snapshots.
  • Mock delivery records and operator audit events.

The application does not extract data from invoice photos or PDFs. It does not use a trained machine-learning model to classify invoices.

4. How data is stored

Records are stored in a SQLite database on the machine running the demo. The database path is controlled by the deployment operator through the DATABASE_PATH environment variable.

The project does not claim application-level encryption at rest, independent security certification or regulatory compliance. Production access is expected to use OIDC sign-in when APP_ENV=production, but the static site does not configure or verify that deployment.

5. Sharing and third parties

The website code does not include advertising trackers, analytics SDKs, payment processors or a customer relationship management integration. The Streamlit runtime and the hosting provider may process technical data under their own terms; the final processor list has not been confirmed.

The application has a provider integration for the Meta WhatsApp Cloud API, but live WhatsApp delivery is disabled in the current app interface. The demo records mock delivery only. No live message is sent by the demo.

6. Retention and deletion

No automatic retention or deletion schedule is implemented in the application. Demo records remain in the demo database until an operator resets or removes that database. A production retention period and deletion process are [To be confirmed].

7. Cookies and local storage

The static website does not set marketing or advertising cookies. The Streamlit runtime may use cookies, session state, local storage or similar technology for application operation and sign-in. The exact behavior depends on the deployment and has not been independently audited for a public launch.

8. Your choices and rights

Do not enter real business or personal data into the public demo. If a production service is launched, the operator must define how users can request access, correction or deletion, and which legal rights apply. The contact route and response process are [To be confirmed].

9. Contact and changes

Privacy questions and data requests should be sent to [To be confirmed]. The operator identity and address are [To be confirmed]. This draft may change when the deployment, retention policy and processor list are finalized.
